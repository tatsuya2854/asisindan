## うまくいった進め方

**① 実デコーダで検証してから組み込む**

QRは「見た目がそれっぽい」で終わらせず、jsQR で実際に読めることを確認してから入れた。
書き出したPNGのピクセルからデコードして16タイプ全部通した。結果、実機で一発で動いた。

**② 回帰テストを毎回流してから push**

21件。壊した瞬間に気づけたので、直したものが後で壊れることがなかった。

**③ 実機を見てもらう**

**バグ14件のうち4件は、実機のスクショでしか見つからなかった。**
特に「カードの下半分が消える」は、こちらのテスト環境（高さ800px）では絶対に再現しない。
実機は664px。ここは自動テストの外だった。

**④ 手作業を automate できないなら、作業自体を消す**

GA4のカスタムディメンション登録を4つお願いしていたが、
「Chromeで自動でやって」と言われて、環境的にできないと判明。
そこで**登録が要らない作りに変えた**（イベント名を分割、utm_source を使う）。
自動化できないものは、そもそも必要をなくすほうが速い。

## 反省

**① ホスティング先を確認せずに絶対URLを決めた**

`has_pages: false` を見れば GitHub Pages が無効なのは分かった。
commit の check-runs を見れば Cloudflare が動いているのも分かった。
**先に事実を見ずに、想定で書いて本番を壊した。**

**② テスト環境の画面サイズを実機に合わせていなかった**

800px固定で確認していたので、縮んで消えるバグが最後まで見えなかった。
以降は iPhone 13 / SE を含む4端末で確認する型にした。

**③ 人に手作業を投げる設計にした**

そもそも「GA4で4つ登録してください」と言った時点で設計が悪い。
指摘されるまで気づけなかった。

**④ 「動いている」と「そう見える」を区別していなかった**

魔法陣は計測上ちゃんと回っていたが、絵が左右対称なので回転が伝わらず、
中央の「?」だけが傾いて壊れて見えていた。
**数値で動作を確認しても、見え方の確認にはならない。**
